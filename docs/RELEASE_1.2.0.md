# 1.2.0：通用同步生命值识别

1.1.3 固定写原版生命值字段，在独立血池实体上可能没有实际效果。
本版让 SA、SE 的百分比伤害共用运行时读取追踪，运行代码不按 BOSS 类名、模组 ID 或专用方法名选择血池。

## 处理方式

1. 只在当前线程主动调用目标 getHealth() 的短暂区间，记录 SynchedEntityData.get() 返回的 Float 数据。
2. 只有读取到目标自身唯一的 Float 同步字段，且其值与返回血量一致，才将该字段视为候选血池。
3. 使用同步数据的正常 setter 写入扣血结果，保留脏标记、客户端同步及原生更新回调。
4. 再次读取血量，检查实际扣血和字段是否变化。战斗记录使用实际减少量，失败时不记录虚假百分比伤害。
5. 下一 tick 只读观察是否回血；不强制回写、不锁血、不取消回血。

每次命中重新观察当前分支，避免同类不同实体、维度或阶段切换后使用旧血池。
没有攻击时的反射扫描、字节码扫描或试探性伤害。后续观察队列最多 256 项，使用弱引用。
没有新增模型、纹理或特效实体。

## 支持边界

- 支持原版 Float 同步生命值，以及通过辅助方法/条件分支返回的单一自定义 Float 同步生命值。
- 多个浮点同步字段参与读取、读取其他实体血量、读出值与返回值不一致、未观察到字段时拒绝写入。
- 不支持通用解析普通成员字段、Capability、加密/多血池计算、每 tick 强制恢复等任意生命值机制。
- 运行时追踪不是任意 getter 的静态数据流证明；特殊计算恰好等值、其他模组拦截 setter、独立 HUD 缓存等仍需实测。
- 原有 250%×2 普通伤害仍走原生流程。生命百分比、概率、冷却和存档配置保持原值。
- 归零交给原生死亡逻辑，不移除 BOSS、不跳过阶段演出、不伪造掉落。

## 验证记录

独立 Forge 47.3.22 GameTest 环境；测试代码不进入成品 JAR。

- 自定义血池、同值无关字段、同类不同实例、同实体分支切换、同步脏标记。
- 拒绝混合/计算/常量/其他实体 getter；异常后清理追踪；普通与自定义血量归零。
- SA 两段与 SE 实际事件路径使用自定义血池；保留原有战斗/配方/配置回归。
- 勇者之章组件：启示录 2.2.7、RevelationFix 3.8、对应 Goety 与依赖，16 项 required 测试通过。
- 落幕曲组件：启示录文件 2.3.1（内部 mod 版本 2.3）、RevelationFix 4.0、对应 Goety 与依赖，16 项 required 测试通过。
- 上述组件环境使用重锋 1.1.23；重锋 1.8.62 的基础环境也通过 16 项 required 测试，其中两项可选 BOSS 测试因未装相应模组跳过，实际执行 14 项。

实际下界亚伯伦组件测试：默认最大生命 666，两次分别减少约 66.6，扣后约 532.8；
执行一次原生 tick 后约 533.8，增加的 1 点是原生回血，没有恢复原血池。
血量归零后原生死亡计时达到 1。未完整播放死亡演出或验证最终掉落、全整合包联机与帧率。

测试环境只使用本地组件副本，不修改原整合包或玩家存档。
通过 tools/prepare_health_test_mods.py 准备 libs/ 下本地依赖后运行：

```powershell
./gradlew.bat --offline runGameTestServer -PrunDir=run-health-yuusha -PhealthBossTests=yuusha
./gradlew.bat --offline runGameTestServer -PrunDir=run-health-lmq -PhealthBossTests=lmq
```

相关 BOSS 专用方法名只出现在不随成品分发的测试准备代码。

## 安装与诊断

用 1.2.0 替换旧 JAR；客户端和服务器均更新，原配置与刀的物品数据继续使用。
`/eldenblade health <单个实体选择器>` 只读显示当前服务端血量与识别状态。
日志中的 unsupported/ambiguous 表示未识别；write resisted 表示写入后未达到目标血量。
识别状态不等于对该 BOSS 所有阶段和死亡机制的完整兼容保证。
